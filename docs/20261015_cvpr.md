# CineWorldSim 工作梳理与 CineWorldSim\-Bench 数据构建规范

**核心问题：长叙事视频生成不仅需要保留原始故事，还需要在不破坏既有叙事约束的前提下，对故事进行合理、丰富的视觉化展开**

# 一、研究背景与问题定义

## 1\.1 两类常见创作条件

梳理现有长叙事视频生成工作与实际创作流程，可以看到两类典型的输入条件。第一类是**固定故事板/分镜条件下的视频生成**：创作者已经给定较完整的故事、场景或分镜，系统需要将这些内容转化为视频，并在不同镜头和场景间维持叙事与视觉上的一致。第二类是**基于简短创意梗概或故事线的视频生成**：用户仅提供主要人物、初始情境、核心冲突和大致走向，系统需要进一步形成足以支撑长视频的事件发展、人物互动、情节衔接与分镜安排。

这两类任务的输入条件不同，但共同要求生成的视频既能充分表达故事，又能在跨场景、跨镜头的过程中维持人物行为、事件发展和世界状态的连续性。围绕这两类任务，可以分别观察到以下两个相互关联的问题。

## 1\.2 问题一：固定故事与分镜条件下，原始叙事信息在逐级转换中容易被弱化

长叙事视频生成通常采用“**故事/剧本 → 事件/场景 → 分镜 → 图像/视频**”的逐级转换流程。该流程便于拆分任务和组织执行，但每一级都可能重新概括上一级的信息。当局部规划主要依据当前节点描述，而没有充分结合全局故事、历史状态与相关视觉证据时，细粒度内容就可能在转换中被弱化或遗漏。

容易损失的内容包括人物行动的动机线索、事件之间的因果桥接、角色关系的微妙变化、对后续剧情有作用的物体状态，以及使角色行为成立的情绪与互动细节。此时，即使生成模型严格执行最终分镜，输出仍可能出现“局部画面看起来合理，但没有完整表达原始故事”的情况，并进一步表现为跨镜头叙事衔接不足、叙事内容稀疏、叙事漂移或视频表达与剧本意图不一致。

因此，问题一并不是分镜数量不足，而是：**在给定完整故事和既定分镜的条件下，如何提升跨场景、跨镜头的叙事保真与一致性，尽可能保留原故事中的必要事件、人物关系和细粒度内容，同时补充分镜未充分表达的信息而不改写原有剧情意图？**

## 1\.3 问题二：简短故事线条件下，叙事拓展的丰富度与约束一致性难以兼顾

真实创作中，用户经常只提供简短概要，包括主要人物、初始情境、核心冲突和大致走向。这样的输入通常不足以确定长视频所需的完整事件序列、人物互动、因果衔接和分镜安排，生成过程需要补足故事尚未明确给出的发展内容，形成足以支撑长叙事视觉表达的具体行动与事件关系。

但拓展并非越多越好。若缺少对原故事前提和人物设定的持续约束，新增剧情可能改变人物动机、偏移核心冲突、造成状态前后矛盾、重复已有情节，或通过与原故事不兼容的支线制造表面上的丰富度。结果可能“内容更多”，却没有提升故事表达质量，甚至损害人物、环境和情节的连续性。

因此，问题二的核心不是能否续写，而是：**当输入故事线的信息较为稀疏时，如何在不偏离故事前提、人物设定和核心冲突的情况下，合理拓展叙事内容，并增强长叙事视频的视觉表达与叙事一致性？**

## 1\.4 核心研究命题

两个问题对应不同的输入条件，却具有互补关系：固定分镜任务需要从全局叙事中恢复并融合逐级转换时被压缩的细节；开放式创作任务则需要在故事线约束下构建尚未明确给出的剧情。若系统只依赖逐层文本转换，原有叙事信息容易丢失；若系统只追求自由生成，又容易破坏原有叙事约束。

由此，CineWorldSim 关注的核心问题是：

\> **长叙事视频生成不仅需要保留原始故事，还需要在不破坏既有叙事约束的前提下，对故事进行合理、丰富的视觉化展开。**

该命题包含两个需要分别验证的能力：其一，在完整故事与固定分镜条件下，能否提升必要事件、人物关系和细粒度内容的保留程度；其二，在简短故事线条件下，能否产生更多有叙事价值、连贯且符合原故事约束的新增内容。二者不能由单一视觉一致性分数替代，需要方法与评测共同对应。

# 二、CineWorldSim 方法构建

## 2\.1 总体架构：一套推演机制，两条创作路径

CineWorldSim 采用“**共享叙事世界推演 \+ 双路径叙事单元构建 \+ 统一视觉生成**”的总体结构。整体流程为：

**输入解析与初始状态构建 → 叙事世界状态推演 → 根据任务类型进行锚点融合或开放式剧情/分镜构建 → 叙事单元编译 → 事件级视频生成与组织 → 基于 Bench 进行评估。**

三个模块共享同一叙事世界表示，但针对两种输入条件采用不同的叙事单元构建策略。这样可以将“保留已有信息”与“补足尚未给出的内容”纳入统一方法框架，同时避免把两类任务简化成同一种生成设置。

## 2\.2 模块一：叙事世界状态建模与推演

状态表示为：

$Z_t=(S_t^{\mathrm{nar}},W_t^{\mathrm{vis}})$

其中 $S_t^{\mathrm{nar}}$ 表示事件进展、人物目标、角色关系、故事约束和历史信息；$W_t^{\mathrm{vis}}$ 表示人物外观、地点、物体属性及其相关状态。状态更新表示为：

$Z_{t+1}=\mathcal{T}(Z_t,e_t,H_t)$

该模块为后续内容组织提供显式、可追踪的状态依据：哪些事实已经成立、哪些内容仍未确定、哪些变化需要被后续事件继承，以及哪些内容不能与原故事冲突。对于未被画面或可靠故事证据支持的动机、因果与画外事件，应区分观察事实、推断和未知，避免将推测直接当成事实。

在固定故事与分镜条件下，该模块用于连接全局故事与当前锚点；在简短故事线条件下，则用于维护人物、事件和世界状态在后续内容构建中的一致性。

\- **固定故事与分镜**：梳理全局故事与当前分镜之间的联系，补足相关细节，但不改变既定剧情。

\- **简短故事线**：根据已知设定发展事件、人物互动和状态变化，为剧情与分镜构建提供依据。

## 2\.3 模块二：两类叙事单元构建

### 路径 A：锚点约束式叙事信息融合

输入完整故事 $S$、分镜锚点 $A_i$、世界状态 $Z_{t_i}$、历史信息 $H_i$ 和视觉参考 $R_i$：

$U_i^A=\operatorname{Compile}_{\mathrm{anchor}}(S,A_i,Z_{t_i},H_i,R_i)$

该路径不重新创作整套分镜，而是在保持分镜的核心内容、剧情作用与顺序约束的前提下，将全局故事信息和叙事状态融合到当前锚点中。补充内容可包括人物动作、表情、互动、动机的可观察线索、事件衔接，以及有助于视觉表达的场景和物体细节。

**原则：分镜锚点规定当前镜头需要表达什么；全局故事与叙事状态帮助系统更充分、更准确地表达它。\***该路径重点验证能否减少细节遗漏、叙事漂移和视觉表达与剧本意图之间的不一致。

### 路径 B：故事线驱动的开放式剧情与分镜构建

输入简短故事线 $L$，不提供唯一完整剧情或标准分镜：

$(E,B)=\operatorname{Plan}_{\mathrm{open}}(L,\{Z_t\},H)$

其中 $E$ 为拓展事件序列，$B$ 为分镜计划。随后编译事件生成单元：

$U_i^O=\operatorname{Compile}_{\mathrm{open}}(e_i,Z_i,H_i,R_i)$

系统需自主构建剧情与分镜，在故事线约束下发展合理事件、人物行动、互动与因果衔接。人物身份、核心冲突、关键事实及明确结局要求属于硬约束。开放式创作允许多种合理发展路径，但新增内容必须兼容既有事实、具有叙事推进价值且避免无意义重复。

## 2\.4 模块三：叙事约束下的视觉生成

两条路径进入统一生成流程：

$V_i=\mathcal{G}(U_i,R_i,B_i^{\mathrm{gen}})$

其中 $V_i$ 为事件级视频，$R_i$ 为角色/场景/物体参考，$B_i^{\mathrm{gen}}$ 为生成预算或其他条件。路径 A 对应既定分镜锚点；路径 B 根据自主构建的事件与分镜计划生成并组织视频。“约束”在此指生成前组织叙事单元、状态和参考信息；若没有生成后自动状态验证与修正实现，不应宣称已具备完整闭环校验。

## 2\.5 方法主张与验证映射

|方法主张|核心验证问题|主要证据|
|---|---|---|
|显式叙事状态推演|是否更好保留必要事件、人物行为与关键状态变化？|ER、SS；适用时参考 LVBench\-C|
|状态保持的叙事单元构建|是否减少摘要/分镜传递中的细节遗漏？|ER、SS、FDC|
|约束下的开放式构建与生成|是否产生更多有效、连贯且兼容设定的新增内容？|有效拓展量、EVR、约束兼容性|

# 三、Bench 评测体系

CineWorldSim 研究的是：在长叙事视频生成中，如何通过可追踪的叙事世界状态和双路径叙事单元构建，减少剧情遗漏、状态漂移和无效扩写，并将故事约束持续传递到视觉生成阶段。

因此，实验围绕三个研究问题展开：

CineWorldSim 面向不同叙事输入条件下的长叙事视频生成，设置两个互补的评估 Track，分别研究既有剧情的忠实视觉化与受约束的叙事拓展。

### Track A

剧情锚点给定

输入：完整故事或明确的剧情锚点

目标：保留关键事件，维持人物与世界状态，生成连贯视频

核心问题：剧情有没有被正确呈现？

### Track B

故事梗概给定

输入：简短梗概、核心冲突与人物设定

目标：在保持原始设定的前提下扩展事件，并生成连贯视频

核心问题：故事有没有被合理地扩展？

共同基础：共享叙事世界状态建模、状态约束传递与视觉生成；差异在于叙事单元构建路径及其任务目标。

双 Track 的意义： Track A 检验方法能否忠实地实现既有叙事，Track B 检验方法能否在不破坏原始约束的前提下主动扩展叙事。两者共同验证 CineWorldSim 对不同叙事输入条件的适应能力，而非将故事保持和故事扩写混为一个任务。

双 Track 决定评价目标，三层体系决定评价维度。具体对应如下：

# 二、Track A 主指标：剧情锚点给定

Track A 不评价故事是否扩展得更丰富，主要验证既定剧情能否被正确呈现，以及跨镜头、跨事件的状态是否稳定。

Track A 的重点分析：

- KER 关注“必需事件有没有发生”。

- NSP 关注“事件发生时人物和世界状态是否正确”。

- LNSC 关注“间隔较远的事件之间，已建立的状态是否持续成立”。

三者虽然相关，但评价对象不同，应在标注规范中明确区分，避免重复计算同一错误。

# 三、Track B 主指标：开放式创作

Track B 需要同时评价原始设定保持、长程状态一致，以及新增剧情是否有意义、有因果关系。

## 4\.2 当前关键缺口

1\. **\*\*数据治理\*\***：电影目录数、有效 JSON、辅助文件和有效镜头需统一口径。

2\. **\*\*语义切分\*\***：时间连续分组无法单独区分硬切、动作阶段变化、对话延续与真正微事件。

3\. **\*\*叙事聚合\*\***：尚需建设 L3 场景段落、L4 故事弧与全片设定档案。

4\. **\*\*世界状态\*\***：人物、目标、关系、地点、道具及前后状态需要统一 schema、证据映射和置信度。

5\. **\*\*Bench 真值\*\***：Track A 必要事件/FDC/锚点约束与 Track B 硬约束/有效拓展判据尚需试标与人工审核。

6\. **\*\*评测可靠性\*\***：两阶段防泄漏评测器、人工复核与自动/人工一致性尚待实现。

# 五、四级叙事聚合处理规范

## 5\.1 L1–L4 定义

以下规模是初始工作参考，不是硬性真值。叙事证据优先于固定镜头数或时长。

|层级|名称|典型规模参考|边界原则|CineWorldSim 角色|
|---|---|---|---|---|
|L1|镜头单元 Shot Unit|单个镜头，常见约 2–6 秒|原始镜头标注与源 ID|锚点原子粒度；FDC 底层证据|
|L2|微事件/动作拍 Micro\-Event/Beat|常见 2–8 镜头、约 10–30 秒|时间邻近、空间关系、核心动作/互动连续；硬切或阶段转折可拆分|推演步长 $e_t$，必要事件基础单元|
|L3|场景叙事段落 Scene Segment|常见 1–5 个 L2、约 30–120 秒|局部时空与戏剧目标相对一致|场景级叙事与状态进出变化|
|L4|多场景故事弧/全片描述 Story Arc/Macro\-Story|故事弧常见 2–5 个 L3；全片概要汇总全部有效 L3<br>|跨场景人物状态延续、事件承接与有证据的因果关系<br>|产生 Track A 故事 $S$、Track B 简短故事线 $L$ 与全局上下文|



映射必须可追溯：`L1 shots → L2 micro-events → L3 scene segments → L4 story arcs/movie bible`。时间相邻不等于同一事件；相同地点不等于同一叙事段落；人物重叠只能作为信号之一；仅有时间顺序时标记 `before/after`，不能直接认定 `causes`。



## 5\.2 端到端数据链路



**\*\*阶段 1：清洗与 L2 精修\*\***

**\*\*阶段 2：L2 描述\*\***

**\*\*阶段 3：L2→L3→L4\*\***

**\*\*阶段 4：双轨 Bench\*\***

建立 manifest，至少记录 `movie_id`、`shot_id`、相对路径、哈希、起止时间、时长、序号、解析状态、失败原因、`sequence_id`、描述状态、模型/提示版本与输入哈希。分别统计原始 JSON、辅助 JSON、有效镜头、无效文件、电影目录、有效电影 ID 和序列数量，不能把文件数等同于镜头数。

## 5\.4 P1：L1→L2 语义边界精修

## 5\.6 P2：L2 事件描述生成与质量检查

先在 20–50 部具有代表性的电影上开展试运行，再基于质量、成本与错误类型决定扩展规模。现有两个目录中各 5 个 GPT\-5\.2 样例只能用于检查提示和 schema，不能证明全量质量。

抽样应覆盖不同电影、序列长度、人物数量、对话/动作/环境/转场镜头以及清晰和模糊的事件边界。质量审查至少包括事实忠实度、事件覆盖、时间顺序、人物消歧、因果/动机克制、压缩程度、镜头映射完整性及 JSON 可解析性。结构校验不能代替语义审核。

## 5\.7 P3：L2→L3 场景叙事段落聚合

## 5\.7 P4：L3→L4 全片档案与故事弧

新增 `scripts/build_l4_story_arcs_and_movie_bible.py`，分成两个产物。

**\*\*Movie Bible \& Macro\-Synopsis\*\***：包括 \`movie\_synopsis\`（按故事阶段/幕组织，显式标记较大时间断层）、\`global\_character\_profiles\`（人物身份、可观察特征、已知目标、关系变化）、\`recurring\_locations\_and\_objects\`（跨场景地点/道具及可确认状态）、来源 L3/镜头、未解决不确定项。局部镜头注释不足以支持全片真值时，必须缩小结论范围。

**\*\*Multi\-Scene Story Arc\*\***：从 L3 中选择有跨场景人物状态延续、事件承接或有证据因果关系的组合。2–4 个 L3、约 3–6 个 L2、10–25 个 L1 镜头可作为初始候选范围，不应硬性截断。每个故事弧需有 \`l4\_arc\_id\`、关联 L3/L2/L1 ID、连贯自包含的 \`story\_arc\_text\`、必要人物背景、必要事件候选、FDC 候选、硬约束候选、证据映射、置信度和审核状态。300–600 词可作为初始文本范围，但完整性与可评测性优先于固定词数。



## 5\.8 P5：Track A/B 标注

新增 `scripts/build_cineworldsim_benchmark_annotations.py`。

**\*\*Track A 输入\*\***：\`full\_story\_S\`、按顺序选取的 \`storyboard\_anchors\_A\`、\`visual\_references\_R\` 和统一生成规格。锚点保留当前镜头的构图、表层动作与运镜等必要语义，但不提前写入待模型从全局故事/状态中恢复的全部细节；也不能为了增加难度而删除锚点必要语义或加入源镜头没有的要求。

Track A 真值包含：

- `essential_events_E_source`：必要事件、可判定描述、`source_l2_id`、证据镜头、可观察性；

- `fine_grained_units_FDC`：可观察、可判定的微互动、情绪线索、事件衔接、物体/环境状态；

- `anchor_constraints`：锚点必须保留的语义和顺序；

- `evidence_map`、置信度与人工审核状态。

**\*\*Track B 输入\*\***：\`short\_storyline\_L\`（1–3 句，描述人物、初始情境、核心冲突和大致方向）、适用视觉参考与生成规格。约束字段包括人物、前提/场景、核心冲突、明确结局边界（仅在确有依据时使用）和 \`valid\_expansion\_dimensions\`。

避免循环伪标签：同一 LLM 生成 L2/L3 后，不得不经独立审核就把结果当作真值。记录标签来源、模型/提示版本和置信度，对关键事件、因果、人物目标和硬约束进行人工抽检。



## 5\.9 P6：视觉参考资产

对审核通过的样本建立角色、场景和关键道具参考绑定。记录 `reference_id`、`entity_id`、类型、源电影/镜头/时间、图像路径、选取理由、遮挡/清晰度、许可限制及关联 benchmark 样本。参考图的可用范围需在 Track A/B 中明确；按电影划分数据时避免同一故事参考资产跨集泄漏。不能假定已有完整干净的角色图库。

|层级|必查内容|
|---|---|
|L1|时间码、源文件、字段类型、稳定 ID|

# 八、风险控制与近期行动



1\. **\*\*时间阈值不是语义规则\*\***：\`\<1000 ms\` 和 60 秒仅用于候选筛选。

2\. **\*\*模型幻觉进入真值\*\***：分离观察事实、推断与未知；关键标签人工抽检。

3\. **\*\*局部注释冒充全片故事\*\***：来源不足时只主张片段/故事弧级保真。

4\. **\*\*锚点泄漏或被过度削弱\*\***：保留锚点必要语义，但不预先写入待恢复的全部细节。

5\. **\*\*开放式任务被单一答案限制\*\***：不以原片后续剧情作为唯一答案。

6\. **\*\*指标解释越界\*\***：ER、SS、FDC、有效拓展量与 EVR 各司其职。

7\. **\*\*Bench 指标混用\*\***：ViMax、VBench\-Long、LVBench\-C 与 CineWorldSim\-Bench 分开报告。

8\. **\*\*评估上下文泄漏\*\***：先盲态重建，再对齐源故事/约束。

9\. **\*\*先规模后质量\*\***：不立即对全部 56,929 个序列进行大规模 LLM 调用。

10\. **\*\*许可与复现风险\*\***：发布前核验影片、图像和派生数据许可。



近期执行顺序：

1. 核验电影目录、有效镜头、无效 JSON 与序列统计；

2. 在代表性样本上完成 L2 精修与事件描述质量评估；

3. 完成两部影片的 L2→L3→L4 端到端样例；

4. 人工审核 5–10 个 Track A/B 样板题；

5. 开发两阶段防泄漏评测器；

6. 建立基线并开展三组贡献导向消融；

7. 逐步扩展候选集，分别复现外部 Bench 协议。

研究结论必须由主结果、消融和人工复核共同支持，不预设“所有指标全面领先”。应分别回答状态推演是否改善保真、开放式模式是否产生更多有效拓展，以及视觉一致性、长距离状态保持与叙事表达之间的优势和权衡。
